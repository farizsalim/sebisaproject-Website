SEBISA PROJECT - INVENTARIS KEBUTUHAN CMS
=========================================

Dokumen ini dibuat dari audit halaman utama, komponen React, data JSON, dan aset
di folder public. Isinya adalah daftar data yang perlu dikelola CMS, bukan
implementasi database final.


1. KONDISI WEBSITE SAAT INI
----------------------------

- Framework: Next.js App Router.
- Halaman aktif yang terdeteksi: halaman beranda pada src/app/page.js.
- Data eksternal saat ini:
  - public/data/services.json
  - public/data/case-studies.json
- Konten lain masih hardcoded di komponen:
  - Navbar, Hero, ConsultationSection, ClientsSection, AboutSection,
    FaqSection, FinalCtaSection, Footer.
- Belum ada backend, database, route admin, auth, role, audit log, API CMS,
  upload media, workflow publikasi, atau penyimpanan lead.
- Logo klien saat ini berupa 15 file PNG dengan nama acak di public/Client.
- Aset portfolio saat ini menggunakan gambar/video di folder public/GarlicGo,
  public/Yuk Kebab, dan gambar umum di public/images.
- Nomor WhatsApp konsultasi masih berupa placeholder: 6280000000000.
- Link /tim dan /karir sudah dipakai oleh navigasi, tetapi route-nya belum
  terlihat pada struktur app yang diaudit. Keduanya perlu diputuskan apakah
  menjadi halaman CMS atau link eksternal.


2. ROLE DAN AUTHENTICATION CMS
------------------------------

Entitas User:
- id
- nama lengkap
- email login
- nomor WhatsApp (opsional)
- avatar (opsional)
- role
- status akun: active, suspended, invited
- last login
- created at
- updated at

Role minimum:

1) Super Admin
- Mengelola semua user, role, pengaturan, konten, media, dan publikasi.
- Menghapus atau memulihkan data.
- Melihat audit log dan lead konsultasi.

2) Admin/Content Manager
- Membuat, mengubah, mengarsipkan, dan mengajukan konten.
- Mengelola media dan lead sesuai izin yang diberikan.
- Tidak boleh mengubah Super Admin atau pengaturan auth kritis.

3) Editor/Writer
- Membuat dan mengubah draft copy, service, FAQ, dan case study.
- Tidak boleh mempublikasikan langsung tanpa approval.
- Tidak boleh menghapus permanen atau mengelola user.

4) Media Manager (opsional)
- Upload, mengubah metadata, mengelompokkan, dan mengarsipkan media.
- Tidak boleh mengubah isi copy atau konfigurasi auth.

5) Sales/Lead Manager (opsional)
- Melihat dan menindaklanjuti lead konsultasi.
- Mengubah status lead dan menambahkan catatan internal.
- Tidak boleh mengubah konten website.

Hak akses yang disarankan:
- content.view, content.create, content.edit, content.delete
- content.submit_review, content.approve, content.publish
- media.view, media.upload, media.edit, media.delete
- lead.view, lead.edit, lead.export
- user.view, user.invite, user.edit_role, user.suspend
- settings.view, settings.edit
- audit.view

Auth dan keamanan:
- Login email/password dengan password ter-hash.
- Verifikasi email dan reset password.
- Session aman dengan expiry dan logout semua perangkat.
- MFA untuk Super Admin.
- Rate limit login dan perlindungan brute force.
- Validasi role di server, bukan hanya menyembunyikan tombol di UI.
- Audit log untuk login, perubahan role, edit, publish, unpublish, dan delete.
- Soft delete untuk konten dan media agar dapat dipulihkan.


3. MODEL STATUS DAN PUBLIKASI
-----------------------------

Status konten:
- draft: hanya dapat dilihat oleh pengguna CMS.
- in_review: menunggu pemeriksaan editor/admin.
- approved: disetujui dan siap dipublikasikan.
- published: tampil di website publik.
- archived: tidak tampil, tetapi tetap tersimpan.

Field workflow pada semua entitas konten:
- status
- created by
- updated by
- reviewed by (opsional)
- published by (opsional)
- published at (opsional)
- scheduled at (opsional)
- created at
- updated at
- deleted at (soft delete)
- revision number

Aturan penting:
- Hanya satu versi published yang aktif untuk konten yang sama.
- Draft dapat dipreview sebelum publish.
- Perubahan isi published sebaiknya membuat revision baru.
- Konten wajib memiliki slug unik jika dipakai pada URL.

KESIMPULAN
----------

MVP CMS paling penting adalah auth berbasis role, media library, site settings,
homepage section, service, case study, client, FAQ, serta consultation lead.
Data JSON yang sudah ada dapat dijadikan seed awal. Konten hardcoded perlu
dipindahkan bertahap setelah model CMS siap, dengan referensi ID untuk relasi
dan workflow publish agar perubahan admin aman untuk website publik.
